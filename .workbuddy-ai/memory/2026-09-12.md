### render.timeline bug found and fixed (commit 30deb32)

A still (.jpg) clip produced a **262-byte file with no video stream** — no `-loop 1` — so
`durationOf()` returned 0, every xfade collapsed to `offset=0.000`, and ffmpeg died with
"matches no streams". Fixes: `-loop 1` + skip `-ss` for stills (default 3s if no duration);
throw `CLIP_UNREADABLE` naming the bad clip instead of silently zeroing offsets; delimit the
offset placeholder as `@@OFFn@@` (bare `OFF1` also matches `OFF10` at ≥10 transitions).

### Harness gotchas

- **Pass inputs via `--json <file>`, never `--input k=v`** — HTML/SVG payloads and JSON arrays
  contain quotes/commas no shell escaping survives. Arrays must then be real JS arrays, not
  `JSON.stringify`'d strings (schema rejects a string for `clips`/`cues`).
- `spawnSync('npx', …)` needs `shell: true` on Windows (npx.cmd) — otherwise it fails silently
  with no code/reason. Always surface `r.error` or you get a blank FAILED.
- `drive.mjs` must **merge** into report.json, not overwrite — building recipes one at a time
  silently kept only the last one.
- `export.probe` returns nested `{video:{codec,width,height,fps}, audio:{codec}}`, NOT a `streams`
  array and NOT `codec_name`/`r_frame_rate`.
- Remotion first render ≈80s cold (bundling); a first-attempt PLUGIN_ERROR was transient — retry.
- `fx.vintage` requires `look`; `subtitle.create` requires `cues` as an array.

## Browser automation — Playwright integration (commit bda3ca8)

Choice: **Playwright** over Puppeteer. 6:1 npm download ratio in 2026; auto-waiting kills flaky scripts; rich locators (text/role/label/placeholder/testId/css/xpath); native video recording; multi-engine (Chromium/Firefox/WebKit).

Four new plugins on `core/playwright.ts` (the shared layer):

| plugin | what it does |
|---|---|
| `browser.open` | navigate a real URL, dismiss cookie banners, screenshot (or full page) |
| `browser.act` | run a list of actions with auto-waiting and resilient locators |
| `browser.record_flow` | record MP4 video while actions run; ships partial video on failure |
| `browser.scroll_capture` | walk a page in even steps, screenshotting each stop (for Ken Burns or QA strips) |

Added `browser` to the PluginCategory union (the namespace already existed). **124 plugins, 17 categories.**

### Three things that bit me (fixes in the commit)

- **Chrome Headless Shell does not record video.** Only full Chromium does. core/playwright.ts flips `headless: false` when `videoDir` is set.
- **`video.path()` returns a Promise.** Awaiting it is the difference between a 0-byte failure and a real file.
- **`page.video()` must be captured BEFORE context.close().** After close the page is detached and the call returns undefined.

### Other Playwright gotchas worth remembering

- Strict mode rejects ambiguous targets. Wikipedia's search input has two copies (header + sticky); `getByPlaceholder('Search Wikipedia')` matched both. `getByRole('searchbox', {name:'Search Wikipedia'})` matched exactly one because the aria-label differs.
- `evaluate` runs the JS inside `new Function('page', body)` — there is no `window`/`document` parameter. Use `globalThis.scrollTo(...)` (and `globalThis.document.documentElement`) instead of the bare globals, since this project compiles without the DOM lib.
- `runActions` was made to throw `ACTION_FAILED` naming the failing step index + action type, not a generic stack. So a flaky target tells the driving agent exactly which step needs a better selector.
